## Purpose

This repository documents verifying whether [DAVE](https://github.com/IOES-Lab/dave) (underwater robotics simulation library, currently documented for ROS 2 Jazzy + Gazebo Harmonic) and its multibeam sonar plugin ([PR #44](https://github.com/IOES-Lab/dave/pull/44), CUDA-free WGPU backend) can be updated and run on the next-generation **ROS 2 Lyrical + Gazebo Jetty** combination.

Verified on both macOS (Apple Silicon, native) and Docker (Ubuntu 26.04). This is an **integration smoke test**, not exhaustive validation: DAVE's core packages and a representative set of vehicle and sensor paths were confirmed working end to end. The PR #44 WGPU multibeam-sonar backend builds and selects a WGPU adapter/backend on both platforms (Metal hardware adapter on Mac; `llvmpipe` CPU software adapter in Docker, not a real GPU), and has produced real `PointCloud2` output for its primary world — confirmed on Mac Metal under the pre-migration Jazzy+Harmonic track (2026-07-07) and on Docker under Lyrical+Jetty (2026-07-11); Mac Lyrical+Jetty itself has build + adapter-selection + `/stats`-topic confirmation but no direct `PointCloud2` topic-echo on record. (The 2026-07-20 Docker RAM/CPU load test separately re-confirmed the same launch stays alive under load with real CPU/RAM numbers, but did not itself re-check `PointCloud2` topic content — traceability gap flagged 2026-07-23, not treated as a third independent PointCloud2 confirmation.) See [Verified demos](#verified-demos) for the exact environment breakdown. Simulation-progress stability is still under investigation for two of the three worlds that use this plugin — see [Known issues](#known-issues) — so those are reported as PARTIAL, not a completed validation. Full coverage of every world/vehicle/sensor/launch combination is planned for August (see [Next steps](#next-steps)).

Test-result labels used throughout this document:

| Label | Meaning |
|---|---|
| `SMOKE PASS` | Process launches and stays alive for the test window with no crash signature in the log. Confirms the process doesn't crash — does **not** confirm topic/service data or simulation-progress health. |
| `FUNCTIONAL PASS` | Expected topics/services/sensor data were actually read and confirmed, beyond just process liveness. |
| `PARTIAL` | Runs and produces some real output, but has a confirmed functional or performance problem. |
| `NOT AUTOMATED` | Not yet reachable through the current automated (headless) test path — not a claim that it's impossible to test by other means (e.g. RDP/Xvfb, or a modified launch file). |

## Known issues

- **`gui`/`headless` launch argument interaction** — `dave_sensor.launch.py` / `dave_robot.launch.py` / `dave_world.launch.py` (as of the 2026-07-27 fix below) gate the entire Gazebo process on `gui` (`condition=IfCondition(gui)`); `gui:=false` disables Gazebo entirely, not just the window.
