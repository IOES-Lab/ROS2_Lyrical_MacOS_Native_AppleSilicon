- **RESOLVED IN VALIDATED CANDIDATE PATCH 2026-08-29 — `SphericalCoords.cc`'s Lyrical/Jetty migration patch can silently mask a real conversion failure as zero/origin, in *both* conversion directions** (found during the 2026-07-23 documentation audit; fixed in the 2026-08-29 candidate patch) — the new `gz::math::CoordinateVector3`-based API returns `std::optional`s, and the patch substitutes a default value without returning failure whenever those are empty, in both directions:
  - [`TransformFromSphericalCoord`](../patches/dave_lyrical_jetty_migration_mac.diff): only assigns `cartVec` from the result `if (cartOpt && cartOpt->AsMetricVector())`; `cartVec` stays at its default-constructed value (0,0,0) if that check fails, and the service still returns success.
  - `TransformToSphericalCoord` (same patch, confirmed 2026-07-23 while re-checking the first bullet — not previously documented): `response->latitude_deg`/`longitude_deg`/`altitude` are each computed as `(scOpt && scOpt->Lat()/Lon()/Z()) ? ... : 0.0`, so any of the three can silently become `0.0` independently while the service still returns success.

  In both cases, a real request that happens to legitimately resolve near zero/the origin becomes indistinguishable from a silently-failed conversion. The pre-fix branch was not observed to misfire in finite requests. **Runtime update 2026-08-29:** the candidate returns explicit failure instead of substituting a silent default; configured, no-config, invalid-input and paused controls pass on Mac and Docker.
