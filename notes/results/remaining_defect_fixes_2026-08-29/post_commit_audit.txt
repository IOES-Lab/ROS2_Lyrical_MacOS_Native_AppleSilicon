WGPU boundary finding
---------------------

The exact non-power-of-two DFT uses two WGSL workgroup arrays of 4096 f32 values.
The previous host code clamped padded_n to 4096 but did not reject n_freq > 4096;
the exact-DFT loop could therefore index those arrays out of bounds.

- host returns null before slices or GPU initialization when n_freq > 4096
- C++'s existing null-result path performs the CPU fallback
- WGSL independently rejects n_freq > 4096
- a 4097-bin Rust unit test returns null without initializing a GPU
